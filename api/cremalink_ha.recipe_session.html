cremalink_ha.recipe_session module

Per-entry brew-parameter session state.

One RecipeSession per config entry, shared by the recipe select, the parameter number entities, and the brew button. Holds the selected beverage, the loaded RecipeParams, and the user’s pending raw overrides — all transient per spec (no persistence, cleared on recipe/profile change so nothing leaks across recipes).

Machine I/O never happens here directly: async_ensure_params schedules the library’s blocking recipe_params read on the executor exactly once per (recipe, profile) pair; entities watch loading/params.

cremalink_ha.recipe_session.LOAD_RETRY_INTERVAL = 60.0

Minimum seconds between failed param-load attempts — a standby or otherwise unanswering machine must not be flooded with republish requests on every coordinator poll.

property ready: bool

Params loaded for the current (beverage, profile) pair.

_profile_changed only clears params when async_ensure_params next runs — between a profile change and the next coordinator cycle the stale values would otherwise stay brewable/editable. ready is instantaneous: it compares the loaded params’ scope to the live selection and profile. The profile comparison mirrors the brew-side resolution (current_profile or 1 in Device.recipe_params/brew) so an unasserted profile (0) means slot 1, not “never ready”.
