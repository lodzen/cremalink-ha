cremalink_ha.select module

Select platform for the Cremalink integration.

Three selects per contracts/ha-entities.md:

  • Profile picker — occupied 0xA4 slots; selection sends a session-gated 0xA9; state is the last acked slot only.

  • Auto-off + water hardness — session-gated 0x90 writes with 0x95 read-back; state is always a machine-confirmed option.

class cremalink_ha.select.CremalinkProfileSelect(*args: Any, **kwargs: Any)[source]

Bases: _BaseSelect, RestoreEntity

Occupied profile slots; selection is a session-gated 0xA9 write.

Non-striker machines have no current-profile read-back — the app itself stores the selection app-side and only ever tells the machine (0x03EE is the striker register; it does not track 0xA9 selects on Soul). Device.refresh_current_profile therefore returns the last-asserted profile; the remembered selection is also restored after a restart. Like the official app, profile selection is the one setting that is unavailable in standby.
