cremalink_ha.coordinator.DEFAULT_FAILURE_THRESHOLD = 5

Consecutive failed refreshes tolerated before entities go unavailable (FR-035 — a single transient LAN/transport failure must not flap state). At the 1 s awake cadence this means ~5 s of total monitor outage.

cremalink_ha.coordinator.MONITOR_ATTEMPTS = 3

Monitor-fetch attempts per coordinator cycle — the machine drops or delays answers when busy/rate-limited (observed 2026-10-14), and one lost reply must not count as a refresh failure.

cremalink_ha.coordinator.SETTINGS_INTERVAL = datetime.timedelta(seconds=15)

Settings tracking cadence. Panel-side changes republish the backing dNNN datapoint within ~6 s of a request_property GET (protocol.md §14.11); 15 s keeps HA state close to the machine without flooding the single-GET-per-poll command queue.

cremalink_ha.coordinator.STATISTICS_INTERVAL = datetime.timedelta(seconds=300)

Slow-lane statistics fetch cadence (minutes-scale per spec R10 — the 0xA2 paging session and cloud property snapshots do not need fast polls).
